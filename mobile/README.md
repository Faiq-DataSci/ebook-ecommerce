# Mobile (Flutter) – `ebook_store`

## Overview

The **mobile** application is the user‑facing client of the e‑book e‑commerce platform. It is built with **Flutter** (Dart) and follows a clean, layered architecture where UI, state management, and data access are clearly separated. All business‑critical calculations – especially the **Simple Additive Weighting (SAW)** recommendation algorithm – run on the backend; the app only displays the scores returned by the API.

---

## Tech Stack

- **Flutter 3.x** – cross‑platform UI framework
- **Dart** – language
- **Riverpod 2.x** – provider‑based state management (scalable, testable)
- **Dio** – powerful HTTP client with interceptors for auth & error handling
- **Freezed + json_serializable** – immutable data models & JSON (de)serialization
- **Supabase Storage** – obtains signed URLs for protected PDF files
- **flutter_test & mockito** – unit & widget testing

## Environment & Configuration

| Variable            | Description                                                          | Example                     |
| ------------------- | -------------------------------------------------------------------- | --------------------------- |
| `API_BASE_URL`      | Base URL of the backend API                                          | `https://api.myproject.com` |
| `SUPABASE_URL`      | Supabase REST endpoint (used for storage signing)                    | `https://xyz.supabase.co`   |
| `SUPABASE_ANON_KEY` | Public anon key for reading signed URLs (read‑only)                  | `anon-key`                  |
| `JWT_TOKEN`         | Stored after login – injected by `AuthInterceptor` into all requests | –                           |

> **NOTE**: Never commit `.env` or any secret keys to the repository. Use `.env.example` as a template.

## Setup & Development Workflow

1. **Install Flutter** – follow the official Windows installation guide (ensure `flutter doctor` passes).
2. **Get dependencies**
   ```powershell
   cd mobile
   flutter pub get
   ```
3. **Configure environment** – copy the example and fill in values:
   ```powershell
   cp .env.example .env
   # edit .env with API_BASE_URL, SUPABASE_URL, etc.
   ```
4. **Run on an emulator or device**
   ```powershell
   flutter run               # launches on default Android emulator
   # or specify a device
   flutter run -d chrome    # for web preview (optional)
   ```
5. **Testing**
   ```powershell
   flutter test               # unit & widget tests
   flutter test --coverage   # generate coverage report
   ```
6. **Lint & static analysis**
   ```powershell
   flutter analyze            # runs Dart analyzer against analysis_options.yaml
   ```

## Security Considerations

- **API calls** always include the JWT token via an interceptor; expired tokens trigger a graceful logout.
- **PDF access** is via **short‑lived signed URLs** (max 5 min) generated by the backend – the app never stores raw files.
- **Input validation** is performed server‑side; the client only validates user‑friendly constraints (e.g., non‑empty fields) to improve UX.
- **Obfuscation** – release builds use `flutter build apk --release` which strips debug symbols.

---

## Testing Strategy

- **Unit tests** cover use‑cases, repository implementations, and utility functions.
- **Widget tests** verify UI components in isolation, using mocked network responses via `mockito`.
- **Integration test** (optional) runs on a real device/emulator with a staging backend.
- **Coverage target**: ≥ 85 % (enforced by CI).

## Troubleshooting

- **Network errors** – ensure the device/emulator can reach `API_BASE_URL`; check CORS and SSL certificates on the backend.
- **Auth token not attached** – verify `AuthInterceptor` is registered in `ApiClient` and that the token is persisted in secure storage (`flutter_secure_storage`).
- **PDF preview fails** – confirm the signed URL has not expired; regenerate via backend if needed.
